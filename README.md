# Travel Companion

Enter where you are going, the dates and the budget, and get a day-by-day itinerary written by an LLM, with the destination's weather alongside it.

Built by Team GARUDA. Flask + SQLite, server-rendered Jinja templates, OpenAI for the itinerary and Visual Crossing for the weather.

## What it does

- `/` (login required): the trip form — source, destination, start and end date
- Generates a day-wise itinerary: activities, attractions, restaurants and cuisine, estimated costs in INR, local transport tips
- Shows the forecast for the destination over the trip dates
- Accounts: register, log in, log out, passwords hashed with bcrypt
- `/robots.txt` and `/sitemap.xml` are generated by `flask-sitemapper`

## Requirements

- Python 3.10+
- An OpenAI API key
- A Visual Crossing Weather API key (optional; only the weather panel needs it)

## Setup

```sh
python -m venv .venv
. .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env          # then fill it in
```

`.env`:

| Variable | Required | Meaning |
|---|---|---|
| `OPENAI_API_KEY` | yes | used by `llm.py`; without it the itinerary returns a readable error |
| `Weather` | for weather | Visual Crossing key (the variable really is named `Weather`) |
| `SECRET_KEY` | recommended | session signing key; random per start if unset |
| `OPENAI_MODEL` | no | defaults to `gpt-4o-mini` |
| `FLASK_DEBUG` | no | `1` enables the debugger, never in production |
| `PORT` | no | defaults to `5000` |

Run it:

```sh
python app.py                 # http://localhost:5000
```

The SQLite database (`instance/database.db`) and the `User` table are created automatically on first start.

## Layout

```
app.py            Flask app: routes, User model, weather lookup
llm.py            OpenAI itinerary generation
templates/        Jinja pages (index, login, register, dashboard, about, contact, 404)
static/           logo, loading animation, share stylesheet
```

## Routes

| Route | Method | What |
|---|---|---|
| `/` | GET, POST | trip form and generated itinerary (login required) |
| `/login`, `/register`, `/logout` | GET/POST | accounts |
| `/about`, `/contact` | GET | static pages |
| `/robots.txt`, `/sitemap.xml` | GET | generated |

## Notes on this repository

- The files were named `hehe.py` and `bard.py`; they are now `app.py` and `llm.py` (imports updated). `bard.py` never used Google Bard — it always called OpenAI.
- The OpenAI call was on the retired 0.x SDK (`openai.ChatCompletion.create`); it now uses `openai>=1.40` with `client.chat.completions.create` and the same prompt and model.
- Verified with Flask's test client: `/login` returns 200, protected pages redirect to it, and `llm.generate_itinerary()` returns a clear error when the key is missing.

## Known limits

- No CSRF protection, no rate limiting on the itinerary endpoint (each submit costs an OpenAI call), and no tests.
- Weather and itinerary are fetched synchronously inside the request, so a slow upstream means a slow page.
